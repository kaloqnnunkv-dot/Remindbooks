## 0. Подготовка

Отворете терминал в папката на проекта и инсталирайте Railway CLI:

```bash
npm install -g @railway/cli
railway login
```

Отваря се браузър — потвърдете. Това е еднократно.

**Пригответе си текстов файл**, в който ще трупате ключовете от всяка стъпка.
Ще ви трябват накрая, наведнъж.

## 1. Railway: проект и база данни

### 1.1 Създаване на проекта

1. Отворете **https://railway.app/dashboard**
2. Бутон **New Project**
3. Изберете **Deploy from GitHub repo**
4. Ако Railway не вижда хранилището: **Configure GitHub App** → дайте достъп
   до `kaloqnnunkv-dot/Remindbooks`
5. Изберете **Remindbooks**

Railway ще започне автоматичен build. **Той ще се провали** — още няма база
данни. Това е нормално, продължете.

### 1.2 Регион (важно)

1. В проекта → **Settings** (на самата услуга, не на проекта)
2. Секция **Deploy** → **Region**
3. Изберете **Europe West (Amsterdam)**

> Регионът по подразбиране е в САЩ. За български посетители разликата е
> около 150 ms на всяка заявка.

### 1.3 База данни

1. В проекта натиснете **+ Create** (или **New**)
2. **Database** → **Add PostgreSQL**

Railway създава базата за секунди.

### 1.4 Свързване на базата с приложението

1. Кликнете върху услугата на **приложението** (не базата)
2. Таб **Variables**
3. Бутон **+ New Variable** → **Add Reference**
4. Изберете **Postgres** → **DATABASE_URL**

Сега приложението вижда базата.

### 1.5 Временен адрес

1. Услугата на приложението → **Settings** → секция **Networking**
2. **Generate Domain**
3. Копирайте адреса, напр. `remindbooks-production-a1b2.up.railway.app`

**Запишете го — трябва ви в стъпки 7, 8 и по-долу.**

### 1.6 Свързване на CLI с проекта

В терминала, в папката на проекта:

```bash
railway link
```

Изберете проекта **Remindbooks** от списъка.

## 2. Cloudflare R2: хранилище за файлове

Тук ще живеят PDF книгите, аудио записите и кориците.

### 2.1 Активиране на R2

1. **https://dash.cloudflare.com** → лявото меню → **R2 Object Storage**
2. Ако е първи път: **Purchase R2 Plan** → изберете безплатния план

> Изисква карта, но не се таксува под 10 GB съхранение и има **нулева такса
> за трафик** — затова избрахме R2, а не друга услуга.

### 2.2 Създаване на bucket

1. **Create bucket**
2. Име: `remindbooks`
3. Location: **Automatic** (или Европа, ако се предлага)
4. **Create bucket**

### 2.3 API ключове

1. В R2 → отдясно горе **Manage R2 API Tokens** (или **API** → **Manage API tokens**)
2. **Create API token**
3. Име: `remindbooks-app`
4. Permissions: **Object Read & Write**
5. Specify bucket: изберете **remindbooks**
6. **Create API Token**

Показва се екран с ключовете. **Показва се само веднъж** — копирайте и трите:

```
Access Key ID:      → S3_ACCESS_KEY_ID
Secret Access Key:  → S3_SECRET_ACCESS_KEY
Endpoint (S3 API):  → S3_ENDPOINT
```

Endpoint изглежда така: `https://abc123def456.r2.cloudflarestorage.com`

### 2.4 Публичен достъп за кориците

Кориците на книгите трябва да се виждат от всички. Има два начина — изберете
според това дали домейнът е в Cloudflare.

> **Ако при „Connect Domain“ получите съобщение**
> *„That domain was not found on your account“* — това означава, че
> `remindbooks.com` още не се управлява от Cloudflare DNS. Използвайте
> **вариант А** по-долу; нищо не е счупено.

#### Вариант А — r2.dev адрес (работи веднага, без DNS)

1. Отворете bucket-а **remindbooks** → таб **Settings**
2. Секция **Public Development URL** (или **Public access → r2.dev subdomain**)
3. Натиснете **Enable** и потвърдете
4. Cloudflare дава адрес от вида `https://pub-a1b2c3d4.r2.dev`

Запишете го като:
```
NEXT_PUBLIC_MEDIA_HOST=pub-a1b2c3d4.r2.dev
```

Това е напълно достатъчно за пускане на сайта. Адресът от `r2.dev` е с
ограничение на скоростта и Cloudflare не го препоръчва за голям трафик, но
дотогава може да се смени с вариант Б само чрез промяна на тази променлива —
без промяна в кода.

#### Вариант Б — собствен поддомейн (по-добър за дългосрочно)

Изисква домейнът да е добавен в Cloudflare:

1. Cloudflare → **Add a site** → `remindbooks.com`
2. Cloudflare показва два nameserver-а
3. При регистратора на домейна сменете nameserver-ите с тези
4. Изчакайте потвърждение (обикновено до няколко часа)
5. Едва тогава: bucket **remindbooks** → **Settings** → **Custom Domains** →
   **Connect Domain** → `media.remindbooks.com`

```
NEXT_PUBLIC_MEDIA_HOST=media.remindbooks.com
```

> Смяната на nameserver-ите засяга **целия** домейн — включително имейл
> записите от стъпка 3. Ако вече сте ги добавили другаде, пренесете ги в
> Cloudflare, преди да смените nameserver-ите.

Променливата се приема и със, и без `https://` — и двата варианта работят.

## 3. Resend: имейли

Изпраща потвържденията за поръчки и линковете за сваляне.

### 3.1 API ключ

1. **https://resend.com/api-keys**
2. **Create API Key**
3. Име: `remindbooks-production`
4. Permission: **Sending access**
5. **Add** → копирайте ключа (започва с `re_`) → `RESEND_API_KEY`

### 3.2 Домейн (задължително)

Без това всички имейли отиват в спам.

1. **https://resend.com/domains** → **Add Domain**
2. Въведете: `remindbooks.com`
3. Region: **EU (Ireland)**
4. **Add**

Resend показва 3 DNS записа. Добавете ги при регистратора на домейна:

| Тип | Име | Стойност |
| --- | --- | --- |
| MX | `send` | `feedback-smtp.eu-west-1.amazonses.com` (приоритет 10) |
| TXT | `send` | `v=spf1 include:amazonses.com ~all` |
| TXT | `resend._domainkey` | (дълъг ключ от Resend) |

> Точните стойности са във вашия екран в Resend — копирайте оттам, не оттук.

5. След добавяне: **Verify DNS Records**
6. Изчакайте — обикновено 5–30 минути, понякога до 24 часа

Статусът трябва да стане **Verified** (зелено).

Запишете:
```
EMAIL_FROM=Remind Books <noreply@remindbooks.com>
OWNER_EMAIL=  ← имейлът, на който собственикът да получава съобщенията
```

## 5. Stripe: ключове за плащане

> Ако акаунтът още не е одобрен, вижте раздел **Тестов режим** накрая.

### 5.1 API ключове

## 6. Първи деплой

### 6.1 Попълване на променливите

В папката на проекта:

```bash
cp scripts/railway-env.example scripts/railway-env
```

Отворете `scripts/railway-env` и попълнете всичко, събрано дотук.
`AUTH_SECRET` вече е попълнен.

За `NEXT_PUBLIC_APP_URL` въведете временния адрес от стъпка 1.5:

```
NEXT_PUBLIC_APP_URL=https://remindbooks-production-a1b2.up.railway.app
```

`STRIPE_WEBHOOK_SECRET` оставете празен — идва в стъпка 7.

### 6.2 Задаване в Railway

```bash
bash scripts/railway-setup.sh
```

Скриптът задава всички променливи и извежда кои липсват.

> **Алтернатива без CLI:** Railway → услугата → **Variables** → **Raw Editor**
> → поставете съдържанието на файла → **Save**.

### 6.3 Деплой

Railway публикува автоматично при промяна в GitHub. За ръчен деплой:

```bash
railway up
```

Или в интерфейса: **Deployments** → **Redeploy**.

### 6.4 Проверка

1. Отворете временния адрес в браузър
2. Трябва да видите началната страница на Remind Books

Ако има грешка: Railway → **Deployments** → най-горния → **View Logs**.

### 6.5 Начални данни

Еднократно, за да има какво да се види:

```bash
railway run npm run db:seed
```

> Миграциите се прилагат автоматично при всяко стартиране — не е нужно да ги
> пускате ръчно.

**Веднага след това сменете паролата:** влезте на `/vhod` с данните от
конзолата, после **Профил → Настройки → Смяна на парола**.

## 7. Stripe webhook

**Това е най-често пропусканата стъпка.** Без нея поръчките остават „Чакащи“ и
клиентите не получават закупените книги, въпреки че плащането е минало.

1. **https://dashboard.stripe.com/webhooks**
2. **Add endpoint**
3. Endpoint URL:
   ```
   https://ВАШИЯТ-АДРЕС/api/webhooks/stripe
   ```
   (временния адрес от стъпка 1.5, или домейна след стъпка 9)
4. **Select events** → добавете точно тези три:
   - `checkout.session.completed`
   - `checkout.session.expired`
   - `charge.refunded`
5. **Add endpoint**
6. На страницата на endpoint-а: **Signing secret** → **Reveal** → копирайте
   (`whsec_…`)

Задайте го:

```bash
railway variables --set "STRIPE_WEBHOOK_SECRET=whsec_ВАШИЯТ_КЛЮЧ"
```

Railway рестартира автоматично.

## 8. Google вход (по избор)

1. **https://console.cloud.google.com**
2. Горе изберете проекта **Remindbooks** (или създайте нов)
3. Лявото меню → **APIs & Services** → **OAuth consent screen**
   - User Type: **External** → **Create**
   - App name: `Remind Books`
   - User support email: вашият
   - Authorized domains: `remindbooks.com`
   - Developer contact: вашият имейл
   - **Save and Continue** през всички стъпки
4. **Credentials** → **+ Create Credentials** → **OAuth client ID**
   - Application type: **Web application**
   - Name: `Remind Books Web`
   - **Authorized JavaScript origins:**
     ```
     https://remindbooks.com
     https://ВАШИЯТ-RAILWAY-АДРЕС
     ```
   - **Authorized redirect URIs:**
     ```
     https://remindbooks.com/api/auth/callback/google
     https://ВАШИЯТ-RAILWAY-АДРЕС/api/auth/callback/google
     ```
   - **Create**
5. Копирайте **Client ID** и **Client Secret**

```bash
railway variables --set "GOOGLE_CLIENT_ID=..." --set "GOOGLE_CLIENT_SECRET=..."
```

> Пътят трябва да е точно `/api/auth/callback/google`. При разминаване с един
> символ Google отказва входа с `redirect_uri_mismatch`.

## 9. Домейн remindbooks.com

### 9.1 В Railway

1. Услугата на приложението → **Settings** → **Networking**
2. **+ Custom Domain**
3. Въведете `remindbooks.com`
4. Railway показва CNAME стойност — копирайте я

### 9.2 При регистратора на домейна

Добавете записите:

| Тип | Име | Стойност | За какво |
| --- | --- | --- | --- |
| CNAME | `@` или `www` | (от Railway) | самият сайт |
| CNAME | `media` | (от Cloudflare R2) | корици и файлове |
| MX | `send` | (от Resend) | имейли |
| TXT | `send` | (от Resend) | SPF |
| TXT | `resend._domainkey` | (от Resend) | DKIM |

> Някои регистратори не позволяват CNAME на `@`. Тогава използвайте `www` и
> пренасочване от голия домейн, или ALIAS/ANAME запис, ако се поддържа.

### 9.3 Обновяване на адреса

След като домейнът заработи:

```bash
railway variables --set "NEXT_PUBLIC_APP_URL=https://remindbooks.com"
```

**И не забравяйте да обновите:**
- Stripe webhook URL (стъпка 7) → на новия домейн
- Google redirect URI (стъпка 8) → на новия домейн

SSL сертификатът се издава автоматично от Railway. Отнема няколко минути.

## 10. Финални проверки

### 10.1 Тестова поръчка с карта

1. Отворете сайта, сложете PDF книга в кошницата
2. Плащане с тестова карта (ако сте в тестов режим): `4242 4242 4242 4242`,
   произволна бъдеща дата, произволен CVC
3. Проверете:
   - [ ] Пренасочва към страница „Благодарим за поръчката“
   - [ ] Пристига имейл с потвърждение
   - [ ] Пристига имейл с линк за сваляне
   - [ ] В админ панела поръчката е със статус **Платена** (не „Чакаща“)
   - [ ] Книгата е достъпна в **Профил → Моите книги**

> Ако статусът остане „Чакаща“ — webhook-ът не работи. Вижте
> Stripe → Webhooks → вашия endpoint → таб **Events** за грешките.

### 10.2 Останалите проверки

- [ ] Качване на книга с корица и PDF от админ панела
- [ ] Корицата се показва (значи R2 работи)
- [ ] Форма за контакт → съобщението пристига на `OWNER_EMAIL`
- [ ] Абонамент за бюлетин → пристига имейл за потвърждение
- [ ] Забравена парола → пристига имейл
- [ ] Сайтът се отваря нормално на телефон
- [ ] Фирмените данни са попълнени: **Админ → Настройки → Правни документи**

### 10.3 SEO

1. **https://search.google.com/search-console** → **Add property**
2. Изберете **URL prefix** → `https://remindbooks.com`
3. Потвърдете (най-лесно с DNS TXT запис)
4. **Sitemaps** → добавете `sitemap.xml`

## Тестов режим на Stripe

Ако акаунтът още не е одобрен, работете с тестови ключове:

1. В Stripe включете **Test mode** (превключвателят горе вдясно)
2. Вземете `pk_test_…` и `sk_test_…`
3. Направете отделен webhook в тестов режим
4. Тествайте с карта `4242 4242 4242 4242`

Смяната към реални ключове по-късно е само подмяна на 3 променливи.

## Ако нещо се обърка

| Проблем | Причина | Решение |
| --- | --- | --- |
| Поръчките остават „Чакащи“ | Webhook не работи | Проверете URL и `STRIPE_WEBHOOK_SECRET` |
| Имейлите не пристигат | DNS не е потвърден | Resend → Domains → Verified? |
| Кориците не се виждат | `NEXT_PUBLIC_MEDIA_HOST` липсва | Задайте я и redeploy |
| Google вход дава грешка | Redirect URI не съвпада | Точно `/api/auth/callback/google` |
| Build се проваля | Липсва `DATABASE_URL` | Стъпка 1.4 — Add Reference |
| „Плащането не е налично“ | Липсва `STRIPE_SECRET_KEY` | Задайте я и redeploy |

**Логове:** Railway → услугата → **Deployments** → **View Logs**
