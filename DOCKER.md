# Стартиране с Docker

Два начина. Изберете според това какво правите.

---

## Вариант 1 — само да видите сайта

Пуска целия стек (PostgreSQL + приложението) в контейнери. Не изисква
инсталиран Node.js на компютъра.

```bash
# 1. Стартиране (първият път компилира образа — 2-3 минути)
docker compose up -d --build

# 2. Начални данни: категории, 10 книги, блог публикации, админ профил
docker compose --profile seed run --rm seed
```

Отворете **http://localhost:3000**

Или със скриптовете:

```bash
npm run docker:up
npm run docker:seed
```

### Достъп до административния панел

| | |
| --- | --- |
| Адрес | http://localhost:3000/vhod |
| Имейл | `admin@remindbooks.com` |
| Парола | изписва се в изхода на `seed` контейнера |

Паролата не стои в този файл нарочно — хранилището е публично. Ако изходът е
превъртял: `docker compose logs seed`. Може и да я зададете предварително с
`SEED_ADMIN_PASSWORD` в `.env`.

След вход отворете **http://localhost:3000/admin**

### Управление

```bash
docker compose logs -f app     # логове на живо
docker compose restart app     # рестарт
docker compose down            # спиране (данните се запазват)
docker compose down -v         # спиране + изтриване на базата
```

След промяна в кода е нужен нов build:

```bash
docker compose up -d --build app
```

## Вариант 2 — за разработка (препоръчително)

В Docker върви само базата. Приложението се стартира на компютъра, което дава
**мигновено презареждане** при всяка промяна в кода — без повторен build.

```bash
# 1. Само базата
docker compose -f docker-compose.dev.yml up -d
#    или: npm run db:up

# 2. Настройка (еднократно)
cp .env.example .env
```

В `.env` задайте:

```bash
DATABASE_URL="postgresql://remindbooks:remindbooks@localhost:5432/remindbooks"
NEXT_PUBLIC_APP_URL="http://localhost:3000"
AUTH_SECRET="каквото-и-да-е-за-локална-разработка-32"
```

```bash
# 3. Таблици и начални данни
npm run db:push
npm run db:seed

# 4. Стартиране
npm run dev
```

## Какво работи и какво не без външни услуги

Сайтът стартира и се разглежда напълно без нито един външен акаунт.
Функциите, зависещи от външни услуги, са изключени, докато не се добавят
ключове в `.env`:

| Функция | Без ключове | С ключове |
| --- | --- | --- |
| Разглеждане, търсене, кошница | ✅ работи | ✅ |
| Административен панел | ✅ работи | ✅ |
| Качване на файлове | ✅ в папка `./uploads` | S3/R2 |
| Плащане с карта | ❌ бутонът е неактивен | Stripe |
| Имейли | ⚠️ изписват се в конзолата | Resend |
| Бюлетин | ✅ записва се в базата | + MailerLite |
| Вход с Google | ❌ скрит | Google OAuth |

Съобщението „Плащанията с карта в момента не са налични“ на страницата с
кошницата е очаквано, докато няма `STRIPE_SECRET_KEY`.

За да тествате плащания, добавете тестовите ключове на Stripe (`sk_test_…`) в
`.env` и рестартирайте. Тестова карта: `4242 4242 4242 4242`, произволна бъдеща
дата и произволен CVC.

## Чести проблеми

**„port is already allocated“ за 5432**
Имате друг PostgreSQL на компютъра. Или го спрете, или сменете порта в
`docker-compose.yml` на `"5433:5432"` и обновете `DATABASE_URL` съответно.

**„port is already allocated“ за 3000**
Друго приложение заема порта. Сменете на `"3001:3000"` в `docker-compose.yml`.

**Приложението изписва „изчакване на базата“ и спира**
Базата не е стартирала. Проверете с `docker compose logs db`.

**Промените в кода не се виждат**
При Вариант 1 е нужен нов build: `docker compose up -d --build app`.
За ежедневна работа използвайте Вариант 2.

**Искам да започна начисто**

```bash
docker compose down -v          # трие базата
docker compose up -d --build
docker compose --profile seed run --rm seed
```

## Връзка с production

`Dockerfile` е същият, който Railway ще използва при деплой — това, което
работи локално, ще работи и там. Разликите са само в променливите на средата:
реален `DATABASE_URL`, реални Stripe ключове и `NEXT_PUBLIC_APP_URL`, сочещ
към домейна.

Пълните инструкции за пускане на живо са в
[АКАУНТИ-И-ДЕПЛОЙ.md](./АКАУНТИ-И-ДЕПЛОЙ.md).
